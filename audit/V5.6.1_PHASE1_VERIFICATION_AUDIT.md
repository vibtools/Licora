## Root Cause RC-001 — Dashboard DB Fixture Cleanup

### Baseline defect

The v5.6.0 Dashboard integration test cleanup list dropped:

1. `v2_audit_logs`
2. `v2_device_credentials`
3. base Dashboard fixture tables

but did not remove the dependent `v2_refresh_tokens` and `v2_used_nonces` tables left by the preceding API v2 DB integration test.

### Corrective implementation

v5.6.1:

- disables FK checks only during fixture isolation
- drops the full relevant dependent v2 table set
- re-enables FK checks in `finally`
- recreates the minimum v2 schema required by the Dashboard fixture
- verifies the complete five-table API v2 schema readiness fact
- keeps all production schema/migration code unchanged

## Root Cause RC-002 — Dashboard JSON Contract Mismatch

### Baseline defect

`docs/DASHBOARD_DATA_CONTRACT.md` declared top-level:

`data.recent_activity`

but the actual endpoint exposed recent activity only under:

- `api_activity.v1_tracked.recent_calls`
- `api_activity.v2_tracked.recent_events`

### Corrective implementation

v5.6.1 keeps those existing nested fields and additionally exposes:

```json
"recent_activity": {
  "v1_tracked": [],
  "v2_tracked": []
}
```

No external API v1/v2 contract is changed; this is an internal authenticated admin endpoint.

## Root Cause RC-003 — API v2 Ready False Positive

### Baseline defect

Dashboard UI considered API v2 ready when:

- v2 schema existed
- public signing key file existed

This could display `Ready` even if the server private signing key was missing, unreadable, invalid, or mismatched.

### Corrective implementation

v5.6.1 requires:

- complete v2 table set
- readable, parseable public key
- readable private key
- `V2KeyManager::assertPairMatches()` success

The Dashboard endpoint exposes only readiness booleans. It never returns the private key, key PEM, credentials, or key filesystem path.

## Chrome/Browser Finding

- `chrome.exe`
- Google Chrome download URLs
- Chrome installer/downloader code
- browser-launch shell/process calls
- desktop launcher scripts

No Licora runtime implementation that downloads or launches Google Chrome exists.

Therefore the reported “Google Chrome unavailable → Chrome download failed” behavior cannot be attributed to this repository and no speculative Chrome installer/downloader was added. v5.6.1 adds a verifier guard against introducing a Chrome-specific runtime dependency.
