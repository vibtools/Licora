# Licora v5.5.0 UI Forensic Audit

## Baseline

- Official source baseline: Licora `v5.4.1`
- Baseline commit: `53fd8736965d2f99687d23e21ff602b9ed842e18`
- UI reference: VibTools Web UI v2.1.2
- Brand source: supplied Licora branding package

## Confirmed root causes

1. The v5.4 shell migration imported the correct VibTools foundation but retained Bootstrap-heavy page composition and non-compact table/form layout.
2. Descriptive page/card/helper copy survived the migration and violated the compact/no-growth target.
3. Tables lacked one shared compact toolbar/action-menu contract, producing narrow tables and inconsistent actions.
4. Settings exposed multiple stored values that are not enforced by the current runtime, creating misleading controls.
5. Supplied Licora brand assets existed outside the official tracked tree and were not consistently used by the application shell.
6. `tests/updater_builder_contract.py` assumed a `python3` executable, which fails on Windows installations that expose Python only as `python`.

## Corrective implementation boundary

The release is limited to UI composition, Settings truthfulness, verified branding, public API-v2 key metadata/download, documentation/tests and release identity. API v1/v2 protocol/crypto, licensing/device behavior, database schema, cron semantics, authentication/roles and updater protocol/state machine remain frozen.

## Security decision

The API v2 server private signing key is not exposed through the browser. The UI may report key-pair status and public fingerprint and may provide an authenticated Super-Admin public-key PEM download only.
