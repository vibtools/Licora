## Root cause

The Admin UI is pinned to Bootstrap Icons 1.8.1. The class `bi-devices` is not available in that pinned icon set, so device glyphs rendered as blank in several Admin surfaces. v5.8.1 corrected only the two Dashboard instances, leaving seven runtime occurrences in six files.

## Corrective runtime scope

Exactly seven runtime occurrences were changed from `bi-devices` to `bi-laptop`:

1. `admin/includes/ui/navigation.php` — shared sidebar Devices item.
2. `admin/settings.php` — Devices management shortcut.
3. `admin/device.php` — Device Management page heading.
4. `admin/device.php` — empty-state device icon.
5. `admin/license.php` — View Devices row action.
6. `admin/backup.php` — Devices CSV export action.
7. `admin/about.php` — Device Control capability card.

No Dashboard data/refresh code was changed; the Dashboard already used `bi-laptop` in v5.8.1.

## Regression gate

`tests/ui_component_contract.php` now recursively checks Admin runtime PHP, JavaScript and HTML sources and fails if the unsupported device icon class returns. The check intentionally targets runtime UI sources rather than historical documentation/test prose.
