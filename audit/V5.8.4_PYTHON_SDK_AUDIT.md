# Licora v5.8.4 Python SDK Audit

## Scope

The Python component is limited to an optional Secure API v2 client SDK, examples, documentation, tests, CI and release packaging. The final v5.8.4 updater metadata additionally carries the already-reviewed additive v5.8.3 Admin API migration solely to bridge the last published v5.8.2 release; it does not alter Python SDK trust boundaries.

## Protocol findings

- Request signatures bind method, exact path, timestamp, nonce, exact compact JSON SHA-256 and endpoint-specific context.
- The P-256 device private key never enters configuration or snapshots.
- Access tokens fail closed on algorithm, type, key ID, RSA key strength/fingerprint, signature, issuer, audience, App ID, device ID/fingerprint, token version, JTI or time mismatch.
- Redirects, cross-origin paths, non-HTTPS production URLs, oversized responses and incompatible protocol envelopes are rejected.
- Refresh credentials are one-shot; ambiguous refresh outcomes are discarded before activation recovery.

## Session findings

- Windows persists the complete state with current-user DPAPI; macOS/Linux require a system keyring. No plaintext persistence fallback exists.
- Login, validation and logout are serialized. Generation guards prevent a late request from restoring a locally cleared/replaced session.
- Transient online failure can retain authorization only while the signed access token and server-timezone license expiry remain valid.
- Revoked/mismatched device recovery rotates identity at most once in a login attempt.
- Public snapshots contain no license key, token, refresh credential or private key.

## Verification gates

The SDK test suite covers exact transmitted-body signatures, token verification/tampering, placeholder configuration rejection, invalid key short-circuiting, expiry enforcement, lifecycle/logout, refresh degradation, rotated-token retention and device recovery. Dedicated CI installs the distributable package on Python 3.10 and 3.13 for both Linux and Windows.

## Result

Approved as an additive v5.8.4 public-client SDK. Publication additionally requires green Admin API MySQL migration checks and exact-tag release asset verification.
